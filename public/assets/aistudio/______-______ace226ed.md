# 餐车选购清单 · 功能说明书

> UrbanRadar 流动餐车 · 食客端
> 对应源码：`src/components/CartPageView.tsx`（主页面，683 行）+ `src/components/cart/*`（9 个分区组件，1634 行）
> 样式基座：Industrial Precision Console（`--ipc-*` 画布内自持令牌，3px 工业微圆角，不污染全局）

---

## 一、界面定位与入口

| 项 | 说明 |
|---|---|
| 界面性质 | 食客端「餐车选购清单」= 购物车页（全屏独立页，非抽屉） |
| 入口 | ①首页底部悬浮购物车条 → 点购物车图标；②点「去结算」直达结算页（跳过本页）；③底部导航无独立入口 |
| 作用 | 确认已选餐品与定制项、选择履约方式与优惠、查看费用构成、去结算 |
| 设计宽度 | 移动端 430px（内容区 `max-w-5xl`，宽屏自动居中） |
| 底部固定条 | 实付总额 + 直通收银台 + 前往结算（与底部导航栏分层，互不遮挡） |

## 二、页面结构（自上而下 7 个区块）

### 1. 顶部清单头 `CartHeaderSection`
- 左侧：返回按钮（回到菜单页）
- 中间：标题「餐车选购清单」+ 已选件数徽标（如「1 件餐品」）
- 右侧：**清空**按钮（需二次确认）
- 下方：**履约模式切换**（外卖 / 堂食 / 自提 三选一），切换即时重算起送门槛与配送费

### 2. 配送路径详情 `CartDeliveryCard`
按当前履约模式展示不同内容：

| 模式 | 展示内容 |
|---|---|
| 外卖 | 起送点（餐车位置 + 直距，如「静安大悦城北座 1F 中庭 · 直距 420m」）→ 收货点（地址标题 + 详细地址）→ 收货人姓名/电话 → 地址备注（如「放前台即可，无需敲门」）→ **修改**按钮跳地址选择 |
| 自提 | 餐车自提详情：餐车名称与位置，无收货地址 |
| 堂食 | 堂食餐位详情：已绑桌台显示桌号；未绑定则提示「请先扫码或选择桌台，以便餐车精准派餐」+ 选桌入口 |

右上角另有 **VIP 优先制作** 标识（VIP 生效时展示，代表排单优先）。

### 3. 已点餐品明细 `CartItemListSection`
- 标题「已点餐品明细 共 N 份」
- **展示模式切换**：图文 / 纯文字（只显示文字，适合快速核对）
- 每个餐品行：菜品图、名称、已选规格与选项（如「标准份量」「流心温泉蛋（标配）」）、**由 XX 添加**（同桌加购场景）、单价、**分单小计**
- 数量步进器：删除图标 / − / 数量 / ＋
- **同桌分组**：堂食时按加购人分组显示（桌主（你）/ 同桌食客·小林 / 同桌食客·阿强），并给出「分单小计」，便于同桌分摊
- 已退出的条目置灰（`ownerLeft` 状态保留在清单中，便于对账）

### 4. 服务偏好 `CartServiceCard`
三行设置：

| 项 | 可选项 | 说明 |
|---|---|---|
| 优惠抵扣 | 已选券 + 抵扣金额 + **修改** | VIP 默认已选 `UR-VIP5` 立减券 |
| 环保与包装 | 环保甘蔗降解（减碳 25g）/ 标准保温装（锁温 30 分钟） | 选择即 toast 确认 |
| 制作与口味备注 | 「添加备注」 | 备注是**整单级**的，填在弹层里 |

### 5. 起送门槛横幅 `CartMinOrderBanner`
- 外卖：已满足 → 绿色「已满足外卖起送结算标准」；未满足 → 橙色「未达到起送标准 · 还差 ¥X」+ **凑单**按钮（回菜单加购）
- 自提 / 堂食：提示「无配送起送门槛，即点即享车内现烤制作」

### 6. 费用明细 `CartPriceBreakdownCard`（可折叠）
- 折叠态只显示「费用明细」标题 + 展开箭头
- 展开后逐行：

| 行 | 规则 |
|---|---|
| 餐品原价小计 | 所有餐品 `calculatedPrice` 之和 |
| 餐车专送服务 | 外卖配送费 |
| 到车自提（免配送） | 自提模式固定 0 |
| 堂食餐位及服务（免） | 堂食模式固定 0 |
| 优惠券 | 券抵扣额，标注券码 |
| VIP 权益 | VIP 立减额 |
| 渠道直减 / 阶梯满减 | 按当前支付渠道与活动算 |
| 优惠合计 | 上述优惠之和 |
| 剔除优惠后菜品实付 | 用于起送门槛判定 |

### 7. 加份招牌 · 凑单神器
横向滚动的推荐位：从菜单取**尚未加购**的前 6 道菜，一键加购。标题右侧在未达起送线时显示「差 ¥X 起送」，否则显示「先锋食客最爱搭档」。

## 三、底部结算条 `CartBottomCheckoutBar`
- 左：**实付总额**（大号金额）+「已含全部税费、包装费及配送费」
- 右：⚡ 直通安全收银台（图标按钮）+ **前往结算 ¥XX.XX**
- 该条自带 `data-purpose="checkout-bar"` 标记，供右下角缩放控件避让

---

## 四、三种履约模式的差异

| 维度 | 外卖 | 堂食 | 自提 |
|---|---|---|---|
| 起送门槛 | 有（实付满 X 起送） | 无 | 无 |
| 配送费 | 有 | 免 | 免 |
| 桌台绑定 | 不需要 | **必需**，未绑定拦截结算 | 不需要 |
| 取餐码 | 生成核对码 | 生成核对码 | 生成核对码（取餐核心凭证） |
| 加菜方式 | 独立下单 | **同桌加菜**，按人分组，可分单小计 | 独立下单 |
| 附加卡 | 地址卡 | 堂食餐位卡 | 自提详情卡 |

## 五、结算前的四道门（任一不过即拦截）

1. **空清单** → 提示「选购单暂无餐品」，自动跳回菜单页
2. **堂食未绑桌** → 提示「请先绑定堂食桌台」，自动弹出选桌弹层
3. **外卖未达起送线** → 提示还差多少钱，阻止跳转
4. **支付渠道校验未通过** → 提示原因，并**自动切换到推荐兜底渠道**（如商家未开某渠道时降级）

拦截提示均带具体差额/原因，不是笼统报错。

## 六、弹层清单

| 弹层 | 内容 |
|---|---|
| 选择或兑换优惠券 | 可用卡券列表（雷达首单尝鲜券、黑曜石夜市专享券、VIP 专属立减券…）+ 兑换码输入框 |
| 添加制作与口味备注 | 常用标签（免葱姜蒜、多放黑松露酱、现烤焦香、保温密封、咖啡去冰免糖）+ 自由输入 |

| 堂食选桌 | 桌台矩阵、扫码选座、区域筛选、等位号、就餐人数 |
| 直通收银台 | 独立收银台，可直接完成支付 |
| 支付存证 | 支付成功后生成凭证号与取餐核对码 |

## 七、其它可用操作

- **复制清单**：一键把「餐车名 + 就餐方式 + 逐条餐品与金额 + 实付总额」复制到剪贴板，方便发好友或拼单群
- **VIP 优先制作**：VIP 生效时在配送卡右上角展示，商家端排单优先
- **优惠叠加**：券 + VIP 权益 + 渠道立减 + 阶梯满减可叠加，费用明细逐项列出，不做暗箱

---

## 八、数据与同步

- **算价统一**：购物车页、结算页、下单落库共用同一套算价引擎 `computeOrderTotals`，避免三处口径不一致
- **起送线动态**：取自商家配置 `deliverySettings`，商家改配置会通过事件实时推送到购物车，无需刷新
- **地址联动**：自动匹配已保存地址中的联系人/电话/门牌号/备注
- **支付渠道**：从商家支付配置读取，实时校验可用性与限额
- **同桌加菜**：按 participantId 分组，支持分单小计

## 九、注意事项与已知边界

1. **堂食必须先绑桌**，否则进不了结算页——这是硬拦截，不是提示性文案
2. **起送线按「剔除优惠后菜品实付」判定**，不是按原价小计；大额券可能导致「实付够了但门槛不够」
3. **备注是整单级**，不是单品级；单品定制项在菜品详情页选，备注只补充整单要求（如「全部免葱」）
4. **待支付状态下的加菜**需要走同桌加菜合并流程，不是简单追加
5. 「跨餐车购物车合并」与「分类树卡片」两个模块代码已存在但**当前未接入本页面**，暂不在说明范围内
6. 页面使用画布内自持的 `--ipc-*` 令牌，修改样式时不要写进全局 `index.css`，否则会污染首页与商家端
