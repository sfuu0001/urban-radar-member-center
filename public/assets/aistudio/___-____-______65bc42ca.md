# 餐车（流动餐车调度雷达）· 功能说明书

> UrbanRadar 流动餐车 · 食客端
> 对应源码：`src/components/chat/dispatch-radar/`（`DispatchRadarApp.tsx` 2653 行 + `index.tsx` 311 行 + `dispatchRadar.css` 164 行）
> 入口：食客端底部导航第 3 个页签「餐车」

---

## 一、界面定位

这不是一张静态的「餐车列表」，而是一台**流动餐车调度雷达**：把全城餐车的营业状态、排队情况、备餐余量、覆盖半径和协同关系，压在一屏里，让食客判断「该去哪台车」。

| 项 | 说明 |
|---|---|
| 目的 | 1) 看哪台车在营业、在哪、还剩多久；2) 看哪台车不排队、覆盖我；3) 直接呼叫备餐 / 协同转单 |
| 顶栏 | 返回 / 标题「餐车」/ 搜索 / 视图切换（列表 ↔ 全息矩阵） |
| 底部 | 底部导航（点餐 / 消息 / **餐车** / 工单 / 我的）+ 右下角界面缩放控件 |

---

## 二、顶部工具条

| 控件 | 行为 |
|---|---|
| 返回 | 回到点餐首页 |
| 搜索 | 展开输入框，支持「编号 / 商圈 / 菜品」三路匹配；带清空按钮 |
| 图层（Layers） | 切换**列表视图 / 全息矩阵视图**，按钮 tooltip 会提示将切到哪一种 |

---

## 三、基准指挥台（BASELINE DECK）

页面最上方的指挥台卡，展示**当前基准车**（全城距离与方位的参考原点）：

- **车号与名称**：#01 01（重庆摊面），右上角状态徽标（服务中 / 协同中 / 暂停打烊）+ 营业时间流转入口
- **位置与营业时段**：静安大悦城 · 10:30 - 22:30（午市 / 晚市 / 夜宵）
- **四项核心指标**：

| 指标 | 含义 |
|---|---|
| QUEUE | 排队单数（出餐等待） |
| OPEN | 剩余营业时长（小时），跨夜班次也会正确计算 |
| MIN | 起送门槛（配送门槛） |
| RADIUS | 覆盖半径与覆盖面积 |

- **主厨通告行**：今日主厨出炉/备餐通告，带「呼叫备餐」按钮（可直接下单备餐）
- **底部实时指标**：在岗车数、车队均距、出餐时效（即时/时延毫秒）、零排队比例

---

## 四、控制条（ControlStrip）

一行三个控件：

1. **基准选择器** — 点开下拉列出全部餐车，可「设为基准」，当前基准带「当前基准」标记；切换基准后全页距离/方位角重新计算
2. **排序** — 四种：时空近序 / 排队升序 / 余量最长 / 起送最低，按钮上直接显示当前排序词
3. **重新巡检** — 环形箭头，刷新车队状态与遥测

---

## 五、状态筛选条

四个可切换的胶囊标签，带实时计数：

| 标签 | 含义 |
|---|---|
| 全车队 | 所有餐车 |
| 制作中 | 当前基准车正在服务（service） |
| 蜂窝协同 | 同城其它营业车，可互相分流（collaborative） |
| 打烊 | 暂停营业/检修休眠（standby） |

---

## 六、车队矩阵（FLEET MATRIX）

卡片式排列，右上标注站点数与当前排序方式。点击卡片任意位置**展开细则**（TAP TO EXPAND），展开后显示完整指标、营业时间、通告与操作区。

每张卡片包含：

- **车号 + 名称 + 位置**（静安大悦城 / 市北高新 / 陆家嘴…）
- **状态徽标**：服务中 / 协同中 / 暂停打烊
- **主厨通告**（截断至 48 字）
- **三项关键指标**：距离（相对基准车，Haversine 实算）、排队单数、剩余营业时长
- **底部操作区**：
  - **时空细则** — 展开该车的硬件与工况详情
  - **呼叫备餐** — 打开备餐下单通道
  - **••• 更多操作** — 设为基准 / 协同转单 / 刷新数据

矩阵右下角还有 **FLEET OPS 车队运营统计**卡：各状态台数、车队均距、零排队台数、均位客单价等。

---

## 七、全息视图（旋转木马）

切换到全息视图后，矩阵变为**单站大卡旋转木马**：左右滑动 / 箭头 / 圆点切换餐车，一屏聚焦一台车，适合逐台查看。

---

## 八、弹层清单

| 弹层 | 内容 |
|---|---|
| **时空细则** | 车载储能电网（电量进度条、总线电压、预计可用时长）、食品级水箱与循环（净水/灰水负荷，标注演示数据）、冷冻温控、CAN-BUS 2.0B 工控总线监视器（总线负载率、错误帧计数 TEC/REC）、RTK 载波差分（坐标与精度）、5G 双工遥测（时延、TX/RX、通信波特率）、主厨通告、营业时间流转时间线 |
| **跨站蜂窝协同转单** | 显示该车排队单数，选择目标车把订单分流过去（排除自己与已打烊车） |
| **呼叫主厨备餐通道** | 目标站台菜品列表（价格 + 库存/售罄），步进选份量，底部合计与提交；未选菜品时提示「请选择至少一项备餐餐品」 |
| **营业时间流转** | 周期内每次营业时间调整的内容与时间线（常规排期 / 今日调整 / 今日已打烊） |
| **CAN-BUS 硬件诊断** | 工控总线深度诊断面板 |

## 九、三种状态语义

| 状态 | 判定 | 含义 |
|---|---|---|
| 服务中 | 当前基准车 且 营业中 | 本车正在出餐，可呼叫备餐 |
| 协同中 | 同城其它营业车 | 可参与蜂窝协同、互相分流 |
| 暂停打烊 | 营业状态为关 | 检修休眠 / 消杀与水箱补给中 / 已收档 |

---

## 十、数据来源与诚实性边界

这一页刻意区分「真数据」与「演示值」，不混用：

| 字段 | 来源 |
|---|---|
| 车队、位置、坐标 | 本机餐车配置（真实） |
| 营业状态、营业时段 | 真实营业状态配置，营业时段取「今日临时调整 > 周计划 > 常规」生效值 |
| 主厨通告 | 配置中的公告，取历史栈中最新有效一条 |
| 排队单数 | 真实订单统计（pending / cooking / ready） |
| 距离、方位角 | 以基准车为原点的 Haversine 实算 |
| 剩余营业时长 | 按当前时间与营业时段计算，支持跨夜 |
| 遥测时延 / TX / RX | 读取 `navigator.connection` |
| 电量、水温、RTK 等 | **演示值**，只在「时空细则」弹窗出现并标注「演示数据」，不参与任何计算 |

---

## 十一、注意事项

1. **基准车是全页坐标系原点**，切换基准会连带改变每张卡的距离、方位与排序
2. **呼叫备餐与协同转单属于动作类操作**，会写本地状态并广播；协同转单只记审计，不改订单状态
3. **跨车协同只对「协同中」的车开放**，已打烊车不出现在目标列表
4. 备餐通道在菜品库存为 0 时显示「售罄」，不可选
5. 该页与「消息」页联动：社群互动可从卡片跳进协同聊天房间
6. 存在两个尚未接入的遗留模块：`components/chat/trucks-radar`（旧实现）与 `CrossTruckCartModal`（跨餐车购物车合并），当前不生效
